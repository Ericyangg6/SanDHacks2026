## Spike: reading the transcript during a call (PLAN.md T1)

**Question:** can `apps/api` read what the caller said while the call is still in progress?

| Method | Finding | Source |
|---|---|---|
| Real-time monitoring WebSocket, `wss://api.elevenlabs.io/v1/convai/conversations/{conversation_id}/monitor` | Streams transcripts and agent responses live. Enterprise-only, so not available to us. | ElevenLabs docs, real-time monitoring guide |
| `GET /v1/convai/conversations/{conversation_id}` | Returns `status` (`initiated`, `in-progress`, `processing`, `done`, `failed`) and a `transcript` array. The docs do not say whether `transcript` is filled while `in-progress`. **Not tested live.** | ElevenLabs API reference |
| Post-call webhook | Full transcript, but only after the call ends. Too late for a request made during the call. | `apps/api/src/elevenlabs/post-call.ts` |
| Tool call carries the words | The agent passes the caller's words in `said` on `request_help`. Works on any plan. No delay. | `agent/tools/request_help.ts` |

**Decision:** extraction (T4) reads `said`. It does not depend on a live transcript.

**Still open:** the `GET` poll is untested because this machine has no ElevenLabs key. To test it, start a call (`npm run el:call`), run `npm run el:transcript` during the call, and record here whether `turns` grows while the status is `in-progress`, and how many seconds behind it runs. A working poll would let T4 read the whole call instead of one quote.
